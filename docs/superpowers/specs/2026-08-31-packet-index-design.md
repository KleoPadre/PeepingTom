# Дизайн этапа 3: индекс пакетов и поиск

**Дата:** 31 августа 2026 года  
**Статус:** утверждён  
**Связанная спецификация:** `docs/superpowers/specs/2026-08-28-wispwire-tui-design.md`

## Цель

Подготовить независимый SQLite-слой для временной индексации сводок пакетов,
стабильной пагинации и регистронезависимого поиска-подстроки по `Info`.
Этап не меняет пользовательское поведение `wispwire open`: команда остаётся
простым read-only просмотром до появления TUI.

## Границы этапа

Входит:

- SQLite-схема метаданных пакетов и временный файл индекса;
- пакетная вставка сводок пакетов;
- cursor-пагинация в устойчивом порядке;
- FTS5 с токенизатором `trigram` для поиска по `Info` без учёта регистра;
- проверка поддержки FTS5 trigram в `doctor`;
- модульные тесты всего слоя, без реальных PCAP/PCAPNG и запуска TShark.

Не входит:

- изменение команды `wispwire open`;
- Textual-интерфейс и отображение результатов поиска;
- display filter TShark;
- каталоги live-сессий, сегментация, очистка и параллельный worker записи.

## Архитектура

Новый модуль `wispwire.index` предоставляет `PacketIndex`. Экземпляр
создаётся для явно переданного пути к SQLite-файлу, поэтому будущий
`SegmentManager` сможет владеть его жизненным циклом. Сейчас никакие файлы
сессии автоматически не создаются и не удаляются.

Индекс хранит по одной записи на пакет со следующими полями:

```text
global_number
segment_id
segment_frame_number
captured_at
relative_time
source
destination
protocol
length
info
info_casefold
```

На этом этапе `segment_id` и `segment_frame_number` передаются вызывающей
стороной. Для будущего открытия готового файла будет использоваться один
логический сегмент и номер кадра из вывода TShark. `captured_at` допускает
`NULL`, пока источник не поставляет абсолютное время.

`PacketIndex` выполняет пакетную вставку транзакцией. Связанный виртуальный
стол FTS5 содержит `info` и синхронизируется SQL-триггерами при вставке,
изменении и удалении основной записи. Это оставляет единый источник истины
для пагинации и поиска.

## Пагинация и поиск

Порядок выдачи — по `global_number`, затем по внутреннему `rowid`. Следующая
страница принимает курсор последней строки `(global_number, rowid)` и
использует строгое сравнение пар. Поэтому новые пакеты в конце индекса не
дублируют и не пропускают уже показанные строки.

Поиск принимает непустую строку, преобразует её к casefold-виду и выполняет
FTS5-запрос с триграммной токенизацией. Совпадения сортируются тем же
устойчивым порядком и также возвращаются страницами. Пустой запрос — это не
поиск, а обычная пагинация, которую вызов TUI будет выбирать сам.

## Проверка совместимости

`wispwire.sqlite_support` содержит проверку создания временного виртуального
стола `fts5(..., tokenize='trigram case_sensitive 0')`. Она возвращает
структурированный результат с причиной ошибки, а не выбрасывает необработанное
исключение.

`collect_doctor_report` включает этот результат. Команда `wispwire doctor`
явно показывает доступность SQLite FTS5 trigram и предупреждает, что индекс и
поиск недоступны, если проверка не пройдена. `PacketIndex` повторяет проверку
при создании и поднимает специализированную понятную ошибку без создания
частично инициализированной схемы.

## Ошибки и безопасность

- SQL-параметры передаются исключительно placeholders; пользовательский текст
  `Info` и поисковая строка не конкатенируются с SQL.
- Путь к SQLite-файлу контролирует вызывающий код; создание каталогов и очистка
  не входят в этот этап.
- При отсутствии FTS5 trigram индекс не создаётся, а исходные данные и будущие
  сессии не меняются.
- Ошибки SQLite не скрываются: слой индекса отдаёт предметное исключение с
  исходной причиной для последующей обработки в CLI/TUI.

## Тестирование

Нужны unit-тесты, которые подменяют SQLite-соединение там, где требуется
проверить отсутствие FTS5. Они подтверждают:

- успешную и неуспешную диагностику FTS5 trigram;
- хранение всех полей и пакетную вставку в одной транзакции;
- пагинацию без дублей и пропусков при добавлении новых пакетов;
- поиск подстроки с разным регистром в `Info`;
- отсутствие совпадений и обработку некорректного/пустого поискового ввода;
- явную ошибку `PacketIndex`, когда FTS5 trigram недоступен;
- отображение нового статуса в `doctor`.

После реализации выполняются `pytest`, `ruff check`, `ruff format --check` и
`mypy src` из README. Общий план отмечает этап 3 завершённым только после этих
проверок и коммита.
