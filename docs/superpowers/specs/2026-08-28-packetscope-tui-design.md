# Дизайн PacketScope TUI

**Дата:** 28 августа 2026 года  
**Статус:** на утверждении  
**Репозиторий:** WispWire
**Рабочее имя приложения и CLI:** PacketScope / `packetscope`

## 1. Цель

PacketScope — современная терминальная утилита для macOS Apple Silicon и Linux, которая:

- отображает сетевые пакеты в реальном времени;
- открывает существующие файлы PCAP и PCAPNG;
- использует `tshark`, `dumpcap` и `mergecap` как внешний движок Wireshark;
- показывает колонки `No.`, `Time`, `Source`, `Destination`, `Protocol`, `Length` и `Info`;
- поддерживает стандартные Wireshark display filters и отдельный поиск-подстроку по `Info`;
- показывает дерево протоколов и hex/ASCII-дамп выбранного пакета;
- временно хранит live-сессию и удаляет её после выхода, если пользователь явно не сохранил данные.

Приложение не пытается заменить весь Wireshark, самостоятельно разбирать PCAP или реализовывать собственный язык фильтров.

## 2. Объём первой версии

### Входит

- macOS только на Apple Silicon;
- Linux на ARM64 и x86_64;
- Python 3.11 или новее;
- команды `doctor`, `interfaces`, `capture` и `open`;
- live-захват с адаптивным TUI;
- чтение PCAP и PCAPNG;
- display filter через `tshark -Y`;
- регистронезависимый поиск по `Info`;
- остановка, продолжение, перезапуск и сохранение сессии;
- суммарный лимит временной live-сессии 1 ГБ;
- установка на macOS одной командой Homebrew;
- установка на Linux через Homebrew formula.

### Не входит

- поддержка macOS Intel;
- Windows до заключительного этапа проекта;
- собственный декодер сетевых протоколов;
- редактирование пакетов;
- удалённый захват;
- плагины-диссекторы и Lua-интерфейс;
- полноценные аналитические экраны из первоначального ТЗ до завершения основного просмотра и захвата.

## 3. Технологии и лицензии

- Python 3.11+ — код приложения;
- Textual — TUI, реактивные виджеты, стили и тестовый драйвер;
- Typer — CLI-команды и справка;
- SQLite из стандартной библиотеки — временный индекс пакетов;
- `asyncio`, `subprocess`, `pathlib`, `dataclasses` и `shutil` — системная интеграция;
- `tshark` — декодирование, поля, details и display filters;
- `dumpcap` — привилегированный захват, вызываемый TShark, и прямая диагностика интерфейсов;
- `mergecap` — объединение сегментов при сохранении;
- pytest, pytest-asyncio, Ruff и mypy — разработка и проверки.

PacketScope распространяется под MIT. Прямые runtime-зависимости допускаются только с лицензиями MIT, BSD-2-Clause, BSD-3-Clause, Apache-2.0, PSF-2.0 или ISC. Wireshark распространяется под GPL-2.0-or-later и используется как отдельно установленный внешний набор исполняемых файлов; его код и бинарные файлы не встраиваются в PacketScope.

## 4. Архитектура

### 4.1. Основные компоненты

`PacketScopeApp` управляет экранами, фокусом, горячими клавишами и подпиской на события сессии.

`CaptureSession` реализует конечный автомат состояний:

```text
idle → running → stopped → running
                   ├──→ saving → stopped
running → limit_reached
running|stopped|limit_reached → restarting → running
любое состояние → failed | closing
```

`TsharkProcess` формирует аргументы без shell-интерполяции, запускает процесс, читает stdout/stderr и преобразует строки `-T fields` в модели пакетов.

`SegmentManager` создаёт каталог сессии, отслеживает PCAPNG-сегменты, индекс, их суммарный размер и локальную нумерацию кадров. Сегменты закрываются каждые 500 мс. Общий размер всех временных данных сессии ограничен 1 ГБ.

`PacketIndex` хранит метаданные пакетов, связи с сегментами и результаты display filter. Все записи выполняются одним worker-потоком пакетами; чтение использует отдельные соединения SQLite.

`DisplayFilterEngine` проверяет выражение, запускает ограниченное число процессов `tshark -Y` для готовых сегментов и публикует только результаты последнего поколения фильтра.

`InfoSearchEngine` выполняет регистронезависимый поиск-подстроку через временный индекс FTS5 с триграммной токенизацией. Поддержка FTS5 trigram обязательна для поставляемой Homebrew-версии и проверяется в `doctor` до начала индексации.

`PacketDetailsService` запускает `tshark` только для выбранного сегмента и локального номера кадра, возвращая дерево протоколов и hex/ASCII-дамп.

`SaveService` объединяет сегменты во временный файл назначения через `mergecap`, проверяет результат и атомарно переименовывает его в выбранный `.pcapng`.

`SessionCleanup` удаляет только принадлежащие PacketScope каталоги с корректным manifest и UUID.

`DoctorService` проверяет Python, `tshark`, `dumpcap`, `mergecap`, их версии, интерфейсы, права захвата, SQLite FTS5 и доступное место.

### 4.2. Модель пакета

Каждая строка индекса содержит:

```text
global_number
segment_id                 # null только у ещё не закрытого live-сегмента
segment_frame_number       # null только у ещё не закрытого live-сегмента
captured_at
relative_time
source
destination
protocol
length
info
info_casefold
```

`global_number` не меняется при фильтрации. После закрытия live-сегмент перечитывается, provisional-строки получают `segment_id` и `segment_frame_number`; только после этого для них доступны display filter и Details. `segment_frame_number` используется только для обращения к `tshark` внутри конкретного сегмента.

## 5. Live-захват

### 5.1. Запуск

```bash
packetscope capture
packetscope capture --iface en0
packetscope capture --capture-filter "host 192.168.1.4"
packetscope capture --max-size 1GB
```

Без `--iface` TUI открывает экран выбора интерфейса. С переданным интерфейсом захват начинается сразу после проверок.

Захват пишет временные PCAPNG-сегменты и одновременно получает от `tshark -P -l -T fields` колонки для live-таблицы. Пакеты добавляются в очередь сразу, а TUI применяет накопившиеся изменения каждые 50–100 мс. Захват и запись имеют приоритет над перерисовкой интерфейса.

### 5.2. Сегментация и display filter

Display filter нельзя динамически менять в одном процессе, который одновременно захватывает и пишет raw-пакеты. Поэтому raw-захват всегда сохраняет все пакеты текущей сессии, а display filter применяется к закрытым сегментам через отдельные процессы `tshark -Y`.

Новый пакет без display filter виден почти сразу. При активном display filter задержка нового совпадения составляет до 500 мс плюс время разбора сегмента. При изменении фильтра:

1. ввод автоматически обрабатывается после debounce 200 мс;
2. синтаксис проверяется через `tshark`;
3. при ошибке поле и сообщение становятся красными, а таблица сохраняет последний корректный результат;
4. при успехе запускается новое поколение фильтрации всех сегментов;
5. результаты устаревших поколений игнорируются;
6. новые закрытые сегменты автоматически проходят через активный фильтр.

### 5.3. Управление сессией

- `Остановить` корректно завершает процесс; таблица, фильтры и детали продолжают работать.
- `Продолжить` создаёт новый сегмент и добавляет пакеты в ту же общую историю.
- `Перезапустить` требует подтверждения, удаляет все сегменты и индекс текущей сессии, обнуляет счётчики и запускает новый захват.
- `Сохранить` доступно во время захвата и после остановки. Во время захвата текущий сегмент сначала принудительно закрывается, после чего захват продолжается в новом сегменте, а готовые сегменты сохраняются как согласованный snapshot.
- при достижении 1 ГБ захват переходит в `limit_reached`; продолжение блокируется, пока пользователь не перезапустит сессию или не начнёт новую с большим лимитом;
- лимит относится к сумме PCAPNG-сегментов, SQLite-индекса и остальных файлов session root; интерфейс отдельно показывает raw-размер, размер индекса и общий размер.

## 6. Открытие файла

```bash
packetscope open capture.pcap
packetscope open capture.pcapng
```

Исходный файл никогда не изменяется и не удаляется. PacketScope создаёт только временный SQLite-индекс. Индексация идёт потоково: первые строки появляются до завершения обработки всего файла. Прогресс и возможность отмены отображаются в статусной строке.

Display filter запускает `tshark -Y` для исходного файла. Поиск `Info` использует тот же индекс, что и live-режим. Details и hex загружаются по выбранному `frame.number`.

## 7. Фильтрация

В верхней панели находятся два независимых поля.

### Display filter

Полностью сохраняет синтаксис Wireshark/TShark:

```text
udp && ip.addr == 192.168.1.4
dns.qry.name contains "telegram"
tcp.port == 443
```

Приложение не дополняет и не переписывает выражение. `F` переводит фокус в это поле.

### Info search

Пользователь вводит обычный текст без кавычек и `%`:

```text
telegram
```

Совпадение является регистронезависимой подстрокой в любом месте `Info`. `/` переводит фокус в поле. Результат обновляется на каждом символе без `Enter`. Display filter и Info search применяются одновременно: итоговая таблица содержит пересечение результатов. `Esc` очищает активное поле; отдельная команда очищает оба фильтра.

## 8. TUI

Используется утверждённая адаптивная раскладка C.

### Широкий терминал

- сверху: заголовок с источником, состоянием, скоростью, количеством пакетов и размером;
- ниже: `Display filter` и `Info search` с сообщениями валидации;
- слева: виртуализированная таблица пакетов;
- справа: дерево протоколов и переключаемая вкладка hex/ASCII;
- снизу: контекстная панель действий и горячих клавиш.

### Узкий терминал

Панель деталей переносится под таблицу. Второстепенные колонки скрываются в порядке `Length`, `Destination`, `Time`; `No.`, `Protocol` и `Info` остаются видимыми. Минимальный поддерживаемый размер — 80×24.

### Цвета

Цвет кодирует протокол и всегда дублируется текстовой меткой. Базовая схема:

- TCP — голубой;
- UDP/STUN/TURN — оранжевый;
- DNS — фиолетовый;
- TLS — зелёный;
- ICMP — жёлтый;
- ошибки и malformed — красный;
- остальные протоколы — нейтральный цвет темы.

Темы поддерживают тёмный и светлый терминал. Выделенная строка сохраняет читаемый контраст независимо от цвета протокола.

### Нижняя панель

В состоянии `running`: `Остановить`, `Сохранить`, `Перезапустить`, `Фильтр`, `Info`, `Детали`, `Выход`.

В состоянии `stopped`: `Продолжить`, `Сохранить`, `Перезапустить`, `Фильтр`, `Info`, `Детали`, `Выход`.

В состоянии `limit_reached`: `Сохранить`, `Перезапустить`, `Фильтр`, `Info`, `Детали`, `Выход`.

Основные клавиши: `Space` — остановить/продолжить, `R` — перезапустить, `S` — сохранить, `F` — display filter, `/` — Info search, `Enter` — детали, `Tab` — смена панели, `Q` — выход.

Таблица виртуализирована: в Textual создаётся специализированный viewport, который получает страницы из SQLite и не хранит миллион виджетов или строк в памяти.

## 9. Временные данные и безопасность

Каталоги сессий:

```text
macOS: ~/Library/Caches/PacketScope/sessions/<uuid>/
Linux: ${XDG_CACHE_HOME:-~/.cache}/packetscope/sessions/<uuid>/
```

Каждый каталог содержит manifest с UUID, PID, временем старта, версией схемы и списком принадлежащих файлов. При старте удаляются только каталоги с валидным manifest, отсутствующим живым PID и путём строго внутри каталога PacketScope. Символические ссылки и пути с выходом из корня отклоняются.

При штатном выходе, `SIGINT`, `SIGTERM` и `SIGHUP` процесс захвата завершается, затем временная сессия удаляется. После аварийного завершения или `SIGKILL` данные удаляются при следующем запуске. Явно сохранённые файлы находятся вне session root и никогда не участвуют в cleanup.

Аргументы фильтров передаются в `subprocess` списком без `shell=True`. Имена выходных файлов проверяются, существующий пользовательский файл не перезаписывается без подтверждения.

## 10. Ошибки и деградация

- отсутствие `tshark`, `dumpcap` или `mergecap` блокирует соответствующий сценарий и показывает команду установки;
- отсутствие прав захвата открывает `doctor` с инструкцией, но чтение файлов остаётся доступным;
- авария `tshark` переводит сессию в `failed`, сохраняет уже полученные данные и позволяет сохранить или перезапустить;
- переполнение очереди UI не останавливает capture: увеличивается размер batch и уменьшается частота перерисовки;
- ошибки отдельных Details-запросов показываются в панели выбранного пакета и не завершают приложение;
- нехватка диска останавливает захват раньше лимита и сохраняет доступ к уже записанным сегментам;
- сохранение выполняется через `.part`; при ошибке неполный файл удаляется, исходная сессия остаётся.

## 11. Homebrew и Linux

Создаётся отдельный репозиторий tap `KleoPadre/homebrew-tap`.

### macOS Apple Silicon

Публикуются formula и umbrella-cask с одинаковым пользовательским токеном `wispwire`. Установка:

```bash
brew install --cask kleopadre/tap/wispwire
```

Cask зависит от:

- formula PacketScope, которая в свою очередь зависит от formula `wireshark` с CLI-инструментами;
- cask `wireshark-chmodbpf`, настраивающего непривилегированный доступ к BPF.

Установка ChmodBPF может запросить пароль и потребовать перезагрузку или повторный вход. После установки `packetscope doctor` показывает точный статус.

### Linux

```bash
brew install kleopadre/tap/wispwire
```

Formula устанавливает PacketScope, Python и `wireshark`. Права `dumpcap` проверяются отдельно. Если Linux capabilities не настроены, live-захват блокируется, а `doctor` показывает команду `setcap` для фактического пути `dumpcap`; весь TUI никогда не запускается от root.

Formula и cask используют только стабильные GitHub Releases с фиксированными SHA-256. Обновления проверяются в CI через `brew audit`, `brew style`, установку в чистом окружении и `brew test`.

## 12. Тестирование

### Модульные тесты

- парсинг экранированного вывода `tshark -T fields`;
- пакетная запись и пагинация SQLite;
- FTS5 trigram-поиск по `Info` и диагностика отсутствующей поддержки;
- конечный автомат `CaptureSession`;
- подсчёт лимита 1 ГБ;
- проверка безопасных путей cleanup;
- формирование аргументов subprocess;
- отмена устаревшего поколения display filter;
- атомарное сохранение.

### Интеграционные тесты

- чтение минимальных обезличенных PCAP и PCAPNG;
- фильтр `tshark -Y` и поиск `telegram` по `Info`;
- сегментирование, stop/continue/restart и merge;
- завершение тестового процесса захвата;
- обработка повреждённого файла и синтаксической ошибки фильтра.

### TUI-тесты

- появление строк без `Enter`;
- debounce display filter;
- мгновенное обновление Info search;
- адаптивная широкая и узкая раскладка;
- состояния нижней панели;
- навигация с клавиатуры и сохранение фокуса;
- контраст и наличие текстовой метки протокола.

### Проверки релиза

- macOS Apple Silicon в CI или на выделенном runner;
- Linux ARM64 и x86_64;
- установка из собственного tap;
- `packetscope doctor` после чистой установки;
- smoke-тест открытия файла без прав capture;
- ручной smoke-тест live-захвата с ChmodBPF.

## 13. Критерии готовности первой версии

Версия считается готовой, когда:

1. установка на macOS выполняется одной командой umbrella-cask;
2. `doctor` объясняет каждую отсутствующую возможность;
3. live-пакеты появляются в таблице с `Info` без подтверждения ввода;
4. display filter принимает стандартный синтаксис `tshark` и показывает ошибку автоматически;
5. поиск `telegram` находит любую строку `Info`, содержащую эту подстроку без учёта регистра;
6. оба фильтра работают одновременно;
7. выбор пакета показывает дерево протоколов и hex/ASCII;
8. stop/continue сохраняет единую историю;
9. restart удаляет историю только после подтверждения;
10. Save создаёт единый валидный PCAPNG;
11. при 1 ГБ захват безопасно останавливается;
12. временные данные удаляются при выходе или следующем запуске;
13. интерфейс остаётся отзывчивым при пакетном обновлении 50–100 мс;
14. тесты, Ruff, mypy и проверки Homebrew проходят без ошибок.
