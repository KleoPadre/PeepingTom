# Спецификация безопасных временных сессий WispWire

**Дата:** 1 сентября 2026 года  
**Статус:** утверждён для планирования  
**Связанная спецификация:** `docs/superpowers/specs/2026-08-28-wispwire-tui-design.md`, раздел 9

## Цель и границы

Этот этап добавляет изолированное хранилище временных сессий для будущего
live-захвата. Оно создаёт, описывает, измеряет и безопасно удаляет только
собственные временные данные WispWire.

Этап не добавляет команду `capture`, не запускает `tshark`, не меняет
`wispwire open`, текущий read-only TUI, SQLite-индекс, фильтрацию или
сохранение захвата.

## Каталоги

Корень сессий выбирается по платформе:

- macOS: `~/Library/Caches/WispWire/sessions`;
- Linux: `${XDG_CACHE_HOME:-~/.cache}/wispwire/sessions`.

Каждая сессия — новый каталог `<uuid>` непосредственно внутри корня. UUID
создаётся библиотекой Python и проверяется при каждом последующем обращении.
Никакой пользовательский путь не принимается как имя каталога сессии.

## Manifest и файлы

При создании сессии в её корне атомарно записывается `manifest.json`:

```json
{
  "schema_version": 1,
  "session_id": "uuid",
  "pid": 12345,
  "started_at": "2026-09-01T00:00:00+00:00",
  "owned_files": []
}
```

Все значения валидируются при чтении. `owned_files` содержит только
относительные имена файлов непосредственно под session root или в его обычных
подкаталогах. Запись manifest выполняется во временный файл того же каталога
с последующим атомарным переименованием.

API позволяет зарегистрировать созданный сессией файл и вычислить суммарный
размер regular-файлов внутри session root. Символьные ссылки в расчёт не
входят и делают сессию непригодной для автоматического удаления.

## Безопасная очистка

Штатное закрытие удаляет только экземпляр собственной валидной сессии.
Очистка осиротевших сессий просматривает только непосредственные дочерние
каталоги session root и удаляет каталог лишь при всех условиях:

1. имя является UUID;
2. сам каталог и каждый его компонент не являются символьной ссылкой;
3. нормализованный путь остаётся строго внутри корня WispWire;
4. manifest существует, корректен, имеет известную версию схемы и UUID,
   совпадающий с именем каталога;
5. PID из manifest больше не существует.

Любая ошибка чтения, несоответствие, ссылка или путь за пределами root означает
пропуск без удаления. Внешние файлы, включая будущие явно сохранённые PCAPNG,
никогда не передаются cleanup и не могут быть им затронуты.

## Завершение процесса

Будущий владелец live-сессии подключит единый обработчик штатного выхода,
`SIGINT`, `SIGTERM` и `SIGHUP`: он сначала остановит захват, затем вызовет
закрытие временной сессии. Этот этап предоставляет безопасный вызов закрытия,
но не устанавливает обработчики сигналов и не управляет подпроцессами.

После аварийного завершения или `SIGKILL` каталог остаётся на диске и может
быть удалён только на следующем запуске через описанную проверку осиротевших
сессий.

## Ошибки и тестирование

Ошибки файловой системы не приводят к удалению сомнительных данных: API
возвращает ясный результат операции либо безопасно пропускает кандидат на
очистку. Unit-тесты используют `tmp_path` и проверяют:

- выбор корня на macOS и Linux;
- создание и валидацию manifest;
- учёт размера обычных файлов;
- отказ от удаления путей за root, неверных UUID и символических ссылок;
- пропуск активного PID и удаление подтверждённой осиротевшей сессии;
- отсутствие удаления внешних файлов при всех ошибочных вариантах.

Реальные захваты, системные сигналы и каталоги пользователя в тестах не
затрагиваются.
