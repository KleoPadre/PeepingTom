# План реализации WispWire: статус и очередь этапов

**Дата актуализации:** 28 августа 2026 года

**Спецификация:** `docs/superpowers/specs/2026-08-28-wispwire-tui-design.md`

## Название и границы

Единственное название приложения, Python-пакета, CLI и Homebrew-токена —
**WispWire** / `wispwire`. Этот план не меняет согласованные функциональные
требования и дизайн TUI из спецификации. Он заменяет устаревший план и
отражает только фактический прогресс и порядок дальнейшей работы.

## Правило ведения статуса

- `[x]` ставится только после появления кода, теста, требуемой проверки и
  коммита либо после ссылки на уже существующий подтверждённый коммит.
- `[ ]` означает, что результат ещё отсутствует; наличие текста в старом
  плане не является выполнением.
- Перед началом новой задачи исполнитель сверяет этот документ, целевой
  малый план и `git log`; завершённые этапы не реализуются повторно.
- Каждый новый функциональный этап получает отдельный план в
  `docs/superpowers/plans/`, проходит TDD и завершается фактическими
  проверками.

## Очередь оставшейся реализации

### Этап 1: завершить фундамент CLI

- [ ] Добавить команды `wispwire doctor` и `wispwire interfaces` с
  отображением уже существующего отчёта.
- [ ] Добавить тесты команд, проверить установленный entry point и обновить
  README.
- [ ] Закрыть задачи 4–5 в
  `2026-08-28-foundation-doctor-interfaces.md` только после этих проверок.

### Этап 2: открыть готовый захват без TUI

- [ ] Создать отдельный план `open`: модели сводки пакета и адаптер TShark
  для безопасного потокового чтения PCAP/PCAPNG.
- [ ] Добавить `wispwire open PATH` с read-only обработкой исходного файла,
  ограничением количества пакетов и понятными ошибками зависимостей.
- [ ] Подменять TShark в unit-тестах; реальные PCAP/PCAPNG не добавлять в
  Git.

### Этап 3: индекс и поиск

- [ ] Создать SQLite-индекс временной сессии, стабильную пагинацию и
  регистронезависимый поиск-подстроку по `Info`.
- [ ] Проверить доступность SQLite FTS5 и явно сообщать об её отсутствии.

### Этап 4: read-only TUI для файла

- [ ] Подключить Textual, виртуализированную таблицу пакетов, детали
  выбранного кадра и hex/ASCII через TShark.
- [ ] Проверить минимальный размер терминала и клавиатурную навигацию.

### Этап 5: безопасные временные сессии

- [ ] Реализовать manifest, учёт размера, безопасную очистку и удаление
  осиротевших сессий только внутри каталога WispWire.
- [ ] Отдельно протестировать выход путей за корень, символьные ссылки и
  обработчики завершения процесса.

### Этап 6: live-захват

- [ ] Реализовать сегментированный захват через внешние Wireshark CLI,
  конечный автомат stop/continue/restart и лимит 1 ГБ.
- [ ] Добавить snapshot/save через `mergecap`, не меняя исходные файлы.

### Этап 7: фильтрация и полный TUI

- [ ] Добавить display filter TShark с debounce и поколениями результатов,
  не меняя переданное пользователем выражение.
- [ ] Добавить независимый поиск по `Info`, пакетную доставку событий в UI
  и согласованную адаптивную раскладку TUI.

### Этап 8: поставка и приёмка

- [ ] Подготовить Homebrew formula/cask, CI, документацию и проверяемые
  smoke-тесты macOS Apple Silicon и Linux ARM64/x86_64.
- [ ] Провести ручную проверку UI и live-захвата: автоматические тесты не
  заменяют реальный захват пакетов.

## Ближайшая исполнимая задача

Следующей реализуется **этап 1**. Его детальные шаги уже находятся в
`docs/superpowers/plans/2026-08-28-foundation-doctor-interfaces.md`, задачи
4–5. Начинать этап 2 можно только после фактического закрытия этапа 1 и
создания отдельного утверждённого плана `open`.
